Edge add-on

NikTiar™ Secure Edge

Enterprise web & API edge protection on your appliance — WAF, bots, waiting room, and virtual patches — without sending production traffic to a third-party cloud WAF.

What this offering delivers

NikTiar Secure Edge sits in front of your public sites and APIs. One image, two deployment modes: shared multi-tenant edge (Host-scoped isolation) or dedicated single-tenant edge for the strongest isolation.

Controls are configured on the Secure Edge dashboard and mirrored into the Kevantic admin / customer portals for MSSP and tenant visibility.

  • Managed WAF (OWASP CRS) — SQLi / XSS / LFI-class blocks with tunable paranoia and anomaly scoring
  • Security levels & Under Attack Mode — Off through “I’m Under Attack!” with challenge pages
  • Bot Fight, BIC & advanced PoW challenges — reduce scrapers and credential stuffing noise
  • Custom rules, IP / UA firewall, rate limits — Host-scoped so tenants do not bleed rules
  • SSL/TLS modes & edge caching — Flexible / Full / Strict plus Bypass or Standard cache
  • Enterprise pack — API Shield, GraphQL guard, Page Shield (CSP), Waiting Room, virtual CVE path patches, auth hardening, sensitive-data scan, HIBP leak check, Logpush, honeypot paths, mTLS stub
  • Strong isolation — unknown Host → 421; zone Host chaining; dedicated mode drops foreign zones

Deployment SKUs

  • Shared Secure Edge — multi-customer edge node; logical isolation by hostname / zone. Best for MSSP density and fast onboarding.
  • Dedicated Secure Edge — single-tenant node pinned to one customer code. Best for regulated estates, high traffic, or contractually isolated edges.

Same software image; mode is a configuration pin — not a different product lineage.

Primary use cases

  • Public web & customer portals — stop common OWASP attacks before they hit origin apps.
  • API & GraphQL backends — JSON / TRACE / body caps, batch & depth guards for noisy or abused APIs.
  • Launch / ticketed events — Waiting Room smooths flash crowds without melting the origin.
  • Credential stuffing & bot seasons — Bot Fight + PoW challenges + auth path rate limits.
  • Emergency CVE / path exposure — virtual patches for known bad paths (env, actuators, admin tools) while IT remediates.
  • Data-residency & “no third-party WAF” — traffic terminates on your / Kevantic-operated edge appliance, not a hyperscale WAF SaaS.
  • MSSP multi-tenant edges — shared node with Host isolation, or dedicated pins per strategic customer.

Limitations (honest scope)

Clear boundaries help you buy the right module — not oversell.

  • Protects HTTP(S) edges you place behind Secure Edge — it is not a full CDN PoP mesh like a global cloud network.
  • Does not replace endpoint MDR, NDR, or identity ITDR; those remain NikTiar subscription tiers.
  • Origins, DNS cutover, and certificate lifecycle still need IT / change windows.
  • mTLS and some enterprise toggles require ops wiring (CA / client certs) on dedicated edges.
  • Not a substitute for application secure-coding — WAF reduces risk; it does not fix every business-logic bug.

Who should go for it

  • Organizations exposing customer portals, APIs, or ecommerce that need WAF + bot controls.
  • Buyers who want Cloudflare-class edge controls without mandatory traffic exit to a third-party cloud WAF.
  • MSSPs / enterprises that need shared density or dedicated isolation on the same stack.

Usually not the best fit if…

  • You have no public HTTP(S) apps (pure offline / air-gapped estates).
  • You only need outside-in discovery — start with EASM; add Secure Edge when you are ready to terminate traffic.
