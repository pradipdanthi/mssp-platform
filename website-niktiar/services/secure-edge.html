Platform · Edge

NikTiar™ SecureEdge

Enterprise web, API, and edge protection on your appliance — WAF, bot defense, visitor queue, and virtual patches — without sending production traffic to an external cloud edge service.

How it works Applications supported Who should go for it

How it works

NikTiar SecureEdge terminates HTTPS in front of your origins. DNS for each public hostname points at the SecureEdge node. Every request is classified, challenged, or blocked before it reaches your application servers.

  1. Onboard a zone — hostname → origin (IP or upstream URL), TLS mode, and security level.
  2. Apply policy — managed WAF signatures, firewall / UA rules, rate limits, bot / browser challenges, and enterprise controls from the SecureEdge dashboard.
  3. Cut over DNS — visitor traffic hits SecureEdge first; clean traffic is proxied to your origin.
  4. Operate in the Kevantic portals — MSSP admins and customers see sites, events, and health without raw third-party WAF consoles.

One software image. Shared mode hosts many customer zones with Host-scoped isolation. Dedicated mode pins the node to a single tenant for the strongest separation.

Applications & workloads supported

SecureEdge protects HTTP(S) front doors — any stack that speaks web or API over TLS.

  • Customer & partner portals — React / Vue / Angular SPAs, server-rendered portals, reverse-proxied intranet apps published to the internet
  • Corporate & marketing websites — WordPress, static sites, CMS, brochureware with login or forms
  • REST & JSON APIs — mobile backends, B2B integrations, webhook receivers (API protection: JSON content-type, TRACE block, body size caps)
  • GraphQL APIs — batch / depth / alias guards against abusive query patterns
  • Ecommerce & checkout — cart and payment frontends that need bot and credential-stuffing resistance
  • Login & SSO front doors — auth path rate limits, leaked-credential checks (privacy-preserving lookups), challenge pages during active attacks
  • Ticket / launch / flash-sale sites — Visitor queue queues bursts so origins stay healthy
  • Admin & ops UIs that must be internet-reachable — virtual patches for common CVE paths while IT remediates

Not a fit for pure offline / air-gapped estates with no public HTTP(S), or for non-HTTP protocols (SMTP, industrial OT buses) — those stay with other NikTiar modules.

Capabilities (technical)

  • Managed web application firewall — SQLi, XSS, LFI-class blocks with tunable paranoia and anomaly scoring
  • Security levels & elevated attack mode — Off through elevated lockdown with interstitial challenges
  • Bot defense, client integrity checks & browser challenges — scrapers, headless clients, credential stuffing
  • Custom rules, IP / UA firewall, path rate limits — chained to the zone Host so tenants do not bleed rules
  • SSL/TLS modes & edge cache — Flexible / Full / Strict; Bypass or Standard cache with edge TTL
  • Enterprise pack — API protection, GraphQL abuse protection, page security headers (CSP + Referrer + Permissions-Policy), visitor queue, virtual CVE path patches, auth hardening, sensitive-data scan, leaked-credential checks, log forwarding webhooks, honeypot paths, mTLS stub
  • Isolation — unknown Host → HTTP 421; exact Host → that zone’s origin only; Dedicated mode drops foreign zones

Deployment choices

  • Shared SecureEdge — multi-customer edge; logical isolation by hostname / zone. Best for MSSP density and fast onboarding.
  • Dedicated SecureEdge — single-tenant node. Best for regulated estates, high traffic, or contractually isolated edges.

Same image; mode is a configuration pin — not a different product lineage.

Who should go for it

  • Security and IT leaders exposing portals, APIs, or ecommerce who need WAF + bot controls.
  • Buyers who want enterprise edge controls without mandatory traffic exit to an external cloud edge service.
  • MSSPs and enterprises that need Shared density or Dedicated isolation on one stack.
  • Teams already on NikTiar Silver / Gold / Platinum who want the public HTTP edge covered end-to-end.

Usually not the best fit if…

  • You have no public HTTP(S) applications.
  • You only need outside-in discovery — start with EASM; add SecureEdge when you are ready to terminate traffic.
  • You need a global CDN PoP mesh in every country — SecureEdge is an appliance edge, not a hyperscale CDN footprint.

Limitations (honest scope)

  • Protects HTTP(S) edges you place behind SecureEdge — not a worldwide CDN PoP mesh.
  • Does not replace endpoint MDR, NDR, or identity ITDR (those remain NikTiar subscription tiers).
  • DNS cutover, certificates, and origin readiness still need an IT change window.
  • mTLS and some enterprise toggles need ops wiring (CA / client certs) on Dedicated edges.
  • WAF reduces risk; it does not fix every application business-logic bug.
